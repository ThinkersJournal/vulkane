kind: `vulkane-kernel-text` lowers `Stmt::MaskedLoad` and `Stmt::MaskedStore` (ROADMAP 9e)
---
**The shared walker lowers `Stmt::MaskedLoad` and `Stmt::MaskedStore`, so the GLSL, WGSL and MSL emitters (and the HLSL kernel dialect) lower predicated access (ROADMAP 9e).** No emitter lowered them and no ROADMAP row named them. `MaskedLoad` is `if (mask) { l = element; } else { l = fill; }` and `MaskedStore` is `if (mask) { element = value; }`, each through the plain `Load` / `Store` path (so an atomically typed buffer and a pinned float value behave as there): the guard is exactly the IR's meaning, the memory is not touched where the mask is false (no bounds check, no race record). A `select` would still execute the load, which is why it is not used. Tests: `vulkane-test-support::masked_kernel` (256 threads, a load whose index is in range only where the mask holds, a plain store then a masked store over it); a text test per walker emitter (GLSL, WGSL, MSL) pins the guard structure; device tests on GLSL (glslang) and WGSL (naga) run it and check every cell against the host reference. Mutants of the load guard and of the store guard each fail both device tests (the text test alone passes them, so the device tests are what pin the meaning). SPIR-V (its own builder) and HLSL through fishstringer's Slang path still decline the statements: separate steps, recorded in row 9e. Other emitters' output for kernels without these statements is unchanged: the WGSL and SPIR-V goldens are byte-identical and the per-result test counts of the other crates match the parent's gate.
