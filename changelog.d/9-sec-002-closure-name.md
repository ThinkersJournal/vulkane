kind: Fixed: a closure variable named like a Vault token tripped CodeRipper SEC-002 on main (ROADMAP 9g)
---
**`PhysicalDevice` property readers rename a closure variable so the hosted portfolio job stops reporting a committed secret (ROADMAP 9g).** `vulkane/src/safe/physical.rs` read two property flags through a one-letter closure variable; gitleaks' `vault-service-token` rule is `s.` plus 24 characters, and one of the field names is exactly 24 long, so SEC-002 reported a Critical secret that is a Rust field access. The variable is now `f` in both closures; behaviour is identical and the current tree scans clean. An older commit still holds the pattern, so CodeRipper keeps reporting it from history until a fingerprint is allowed (CireSnave's decision); no waiver or allowlist entry was added here. WSP-010 (crate versions) stays open as a versioning decision.
