kind: SPIR-V kernels lower 8- and 16-bit integer buffers and locals (ROADMAP 8e, integer slice)
---
`vulkane-spirv-emit`'s `lower_kernel` accepts `I8`/`U8`/`I16`/`U16` buffer elements and locals inside an `I32`/`U32` kernel (they are not compute dtypes: the IR admits `ConstInt` at I32/I64/U32/U64 only), reached through the wrapping integer `Cast` (sign-extending a signed source, zero-extending an unsigned one, truncating when narrowing; it is no saturating cast). Capabilities `Int8`/`Int16` and `StorageBuffer8BitAccess`/`StorageBuffer16BitAccess` (with `SPV_KHR_8bit_storage`/`SPV_KHR_16bit_storage`) are declared only for the widths a kernel uses; 32/64-bit kernels are unchanged (golden). `required_features` now also names `shader_int8`, `storage_buffer_8bit`, `shader_int16` and `storage_buffer_16bit`: the host must enable them at device creation and **the driver is not a guard**. The plan path still declines these dtypes. Tests: per type on a device (inputs include each type's extremes; sign vs zero extension and wrap at the maximum, `127 -> -128`, `255 -> 0`; the wrong-extension and no-wrap mutants must differ), capability-only-when-used checks under spirv-val. F16/Bf16/FP8/vectors need float kernels first and stay todo.
